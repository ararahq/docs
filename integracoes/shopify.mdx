A Arara **não tem app nem conector nativo para Shopify**. Não existe tela "Integrações → Shopify" nem templates criados automaticamente. A integração é feita com o que a API já oferece:

1. **Seu backend recebe os webhooks do Shopify** e chama `POST /v1/messages` com um template aprovado. Controle total, serve para qualquer evento (pedido pago, envio, entrega).
2. **Endpoint de recuperação da Arara**: uma URL por organização que recebe eventos de carrinho abandonado e pagamento, e dispara o template configurado no dashboard. Serve quando a ferramenta que chama consegue mandar headers e corpo customizados.

<Note>
  **Antes de começar:** número de WhatsApp conectado na Arara, templates aprovados (veja [Templates](/concepts/templates)) e uma API key `ara_live_...`. O endpoint de recuperação depende do plano da organização.
</Note>

## Opção 1: webhook do Shopify no seu backend

### Configure o webhook no Shopify

No admin do Shopify, crie os webhooks (via app customizado ou em **Configurações → Notificações → Webhooks**) apontando para uma rota sua, por exemplo `https://seusite.com/webhooks/shopify`. Eventos úteis:

| Evento Shopify | Uso |
|---|---|
| `orders/paid` | Confirmação de pedido |
| `fulfillments/create` | Pedido enviado, com código de rastreio |
| `checkouts/create` / `checkouts/update` | Base para detectar carrinho abandonado |

Valide o `X-Shopify-Hmac-Sha256` de cada entrega conforme a documentação do Shopify antes de processar.

### Envie o template pela Arara

Exemplo em Node (runtime Node, SDK `@ararahq/sdk` 1.8.1) para `orders/paid`:

```typescript
import { NodeSDK } from '@ararahq/sdk';

const arara = new NodeSDK({ apiKey: process.env.ARARA_API_KEY! });

export async function onOrderPaid(order: {
  id: number;
  name: string;
  total_price: string;
  order_status_url: string;
  customer?: { first_name?: string; phone?: string | null };
  phone?: string | null;
}) {
  const phone = order.customer?.phone ?? order.phone;
  if (!phone) return; // checkout sem telefone: nada a enviar

  await arara.messages.send(
    {
      receiver: `whatsapp:${phone}`,
      templateName: 'pedido_confirmado',
      templateVariables: [
        order.customer?.first_name ?? 'cliente', // {{1}}
        order.name,                              // {{2}} ex.: #1001
        order.total_price,                       // {{3}}
        order.order_status_url,                  // {{4}}
      ],
    },
    { idempotencyKey: `shopify-order-paid-${order.id}` },
  );
}
```

O template `pedido_confirmado` é seu: crie e aprove antes, com o número de variáveis que o código envia. O Shopify reenvia webhooks que não recebem 2xx; a `idempotencyKey` derivada do id do pedido impede mensagem duplicada.

Para `fulfillments/create`, o mesmo padrão com `tracking_number` e `tracking_url` como variáveis.

<Warning>
  O telefone precisa estar em formato internacional (`+55...`). Se o checkout não obriga telefone, parte dos pedidos não terá para quem enviar. Confira nas configurações de checkout do Shopify.
</Warning>

### Carrinho abandonado

O Shopify não envia um evento "carrinho abandonado". O padrão é: grave o checkout em `checkouts/create`, agende uma verificação (por exemplo 1h depois) e, se não houver pedido para aquele checkout, envie o template com o link `abandoned_checkout_url`. O fluxo completo está na [receita de carrinho abandonado](/recipes/abandoned-cart).

## Opção 2: endpoint de recuperação

Cada organização tem uma URL de ingestão. Busque com uma API key com permissão `ADMIN` (chaves com escopo restrito recebem 403 em `/v1/recovery`):

```bash
curl https://api.ararahq.com/v1/recovery/endpoint \
  -H "Authorization: Bearer ara_live_xxx"
```

```json
{
  "code": "ara_rec_...",
  "hmacSecret": "...",
  "active": false,
  "url": "https://ararahq.com/l/ara_rec_..."
}
```

O endpoint nasce desligado. Ative com `PATCH /v1/recovery/endpoint` e `{"active": true}` (ou pelo dashboard), e configure o template de cada evento em Recuperação.

<Warning>
  O campo `url` aponta para `ararahq.com/l/{code}`, que só aceita `GET`. Envie o `POST` do evento para `https://api.ararahq.com/l/{code}`.
</Warning>

Envie eventos para `https://api.ararahq.com/l/{code}`:

```bash
BODY='{"phone":"+5511999999999","name":"João","variables":{"1":"João","2":"R$ 189,90","3":"https://minha-loja.myshopify.com/checkouts/abc"}}'
SIG=$(printf '%s' "$BODY" | openssl dgst -sha256 -hmac "$HMAC_SECRET" | sed 's/^.* //')

curl -X POST "https://api.ararahq.com/l/$RECOVERY_CODE" \
  -H "Content-Type: application/json" \
  -H "X-Arara-Event: cart.abandoned" \
  -H "X-Arara-Idempotency-Key: checkout-abc" \
  -H "X-Arara-Signature: sha256=$SIG" \
  -d "$BODY"
```

- `X-Arara-Event` é obrigatório. Eventos com recuperação configurável: `cart.abandoned`, `payment.failed`, `pix.created`, `boleto.due`.
- `X-Arara-Signature` é o HMAC-SHA256 do corpo cru com o `hmacSecret`, com ou sem prefixo `sha256=` (aqui **sem** timestamp, diferente dos webhooks que a Arara envia para você). Envie sempre, mesmo que hoje não seja obrigatório.
- `X-Arara-Idempotency-Key` evita processar o mesmo evento duas vezes.
- `variables` preenche o template em ordem alfabética das chaves: use `"1"`, `"2"`, `"3"`... (com 10 ou mais variáveis, `"10"` vem antes de `"2"`).
- Resposta `202` com `{ ingestId, status, reason, messageId }`. `status` pode ser `ACCEPTED`, `SENT`, `REJECTED` (por exemplo `INVALID_PHONE`, `OPTED_OUT`) ou `FAILED`.

O template usado e o comportamento de cada evento são configurados no dashboard, em Recuperação. Detalhes em [Revenue Recovery](/recovery).

<Note>
  Os webhooks nativos do Shopify não permitem definir `X-Arara-Event` nem o formato do corpo. Para usar o endpoint de recuperação a partir do Shopify, é preciso uma camada intermediária (seu backend, ou uma ferramenta de automação que permita requisição HTTP com headers e corpo customizados).
</Note>

## Catálogo no WhatsApp

O assistente de IA (Brain) tem a action `META_CATALOG_SEND`, que envia um produto do **catálogo da Meta** (Commerce Manager) como card no WhatsApp. A Arara não sincroniza produtos do Shopify: o catálogo precisa estar configurado na Meta, com os produtos já sincronizados por você. Veja [Brain — Catálogo](/brain/actions/catalog).

## Limitações

- Sem app, OAuth ou sincronização automática com Shopify.
- Sem templates Shopify pré-criados: crie e aprove os seus.
- Pagamento Pix dentro da conversa depende da action `ABACATE_PIX` do Brain, independente do Shopify. Veja [AbacatePay](/brain/actions/abacate-pix).
