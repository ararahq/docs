Um formulário abre por cima da conversa quando o cliente toca no botão da mensagem. Ele responde sem sair do WhatsApp e a resposta chega estruturada no seu webhook, sem link externo e sem texto livre pra interpretar.

O caminho inteiro são três passos: criar o formulário, enviar (num botão de template, ou direto numa conversa aberta) e ler o evento `message.flow_reply`.

<Note>
Disponível do plano Voo pra cima. Abaixo disso a API responde `403 PLAN_FEATURE_LOCKED`.
</Note>

## 1. Criar

Você descreve as perguntas. A Arara gera o Flow JSON, sobe pra Meta e publica na mesma chamada.

```bash
curl -X POST https://api.ararahq.com/v1/flows \
  -H "Authorization: Bearer ara_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Captar contato",
    "category": "LEAD_GENERATION",
    "title": "Fale com a gente",
    "intro": "Leva menos de um minuto.",
    "submitLabel": "Enviar",
    "fields": [
      { "key": "nome",      "label": "Seu nome",            "type": "TEXT" },
      { "key": "email",     "label": "Seu melhor e-mail",   "type": "EMAIL" },
      { "key": "interesse", "label": "O que você procura?", "type": "SELECT",
        "options": ["Conhecer preços", "Tirar uma dúvida", "Falar com vendas"] },
      { "key": "obs",       "label": "Quer contar mais?",   "type": "LONG_TEXT", "required": false }
    ]
  }'
```

Resposta `201`:

```json
{
  "id": "0b7e6a52-3c1d-4f7a-9a55-2f4f6f1f9c10",
  "name": "Captar contato",
  "category": "LEAD_GENERATION",
  "status": "PUBLISHED",
  "responseCount": 0,
  "publishError": null,
  "definition": { "title": "Fale com a gente", "fields": [ { "key": "nome", "label": "Seu nome", "type": "TEXT", "required": true, "options": [] } ] }
}
```

### Campos

| Campo | Regra |
|---|---|
| `name` | Até 120 caracteres, único por número. Só você vê. |
| `category` | `SIGN_UP`, `LEAD_GENERATION`, `SURVEY`, `APPOINTMENT_BOOKING`, `CONTACT_US` ou `OTHER`. |
| `title` | Até 30 caracteres. Aparece no topo do formulário. |
| `intro` | Opcional, até 300 caracteres. |
| `submitLabel` | Até 30 caracteres. Padrão `Enviar`. |
| `fields` | De 1 a 10 perguntas. |
| `fields[].type` | `TEXT`, `LONG_TEXT`, `EMAIL`, `PHONE`, `NUMBER`, `SELECT`, `MULTI_SELECT`, `DATE`, `OPT_IN`. |
| `fields[].label` | Até 80 caracteres. Pergunta longa vira texto acima do campo, você não precisa encurtar. |
| `fields[].options` | Só em `SELECT` e `MULTI_SELECT`: de 2 a 20 opções, até 30 caracteres cada. |
| `fields[].required` | Padrão `true`. |
| `fields[].key` | Opcional. Minúsculas, números e `_`, começando por letra. É o nome do campo no webhook. |

Sem `key`, a chave nasce do texto da pergunta (`Seu melhor e-mail` vira `seu_melhor_e_mail`). Defina a sua quando o handler já existe.

<Warning>
A Meta não deixa editar formulário publicado. Pra mudar perguntas, crie outro e desative o antigo. Por isso as chaves são estáveis: o que você leu uma vez vale pra sempre.
</Warning>

### Quando a publicação falha

Criar são três chamadas na Meta. Se o JSON for recusado, nada é gravado e você recebe `400 INVALID_FLOW` com o motivo. Se só a publicação falhar, o formulário volta com `status: "DRAFT"` e `publishError` preenchido. Retente sem recriar:

```bash
curl -X POST https://api.ararahq.com/v1/flows/{id}/publish \
  -H "Authorization: Bearer ara_live_xxx"
```

Repetir um `POST /v1/flows` que já passou devolve `409 FLOW_NAME_TAKEN` em vez de duplicar.

## 2. Colocar num template

Use o botão `FLOW` com o `id` do formulário. Vale pra um botão por template, junto com outros botões se quiser.

```bash
curl -X POST https://api.ararahq.com/v1/templates \
  -H "Authorization: Bearer ara_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "captar_contato",
    "category": "MARKETING",
    "language": "pt_BR",
    "body": "Oi {{nome}}, conta pra gente o que você procura?",
    "buttons": [
      { "type": "FLOW", "text": "Responder", "flowId": "0b7e6a52-3c1d-4f7a-9a55-2f4f6f1f9c10" }
    ]
  }'
```

Depois de aprovado, envie o template como qualquer outro. Formulário e template precisam estar no mesmo número: formulário, como template, vive na conta WhatsApp em que foi criado.

### Ou mande direto na conversa, sem template

Com a janela de 24h aberta, o formulário vai como mensagem interativa. Não passa por template nem por aprovação da Meta, então é o jeito mais rápido de testar: crie o formulário e mande pra você mesmo.

```bash
curl -X POST https://api.ararahq.com/v1/messages \
  -H "Authorization: Bearer ara_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "receiver": "5588999990000",
    "interactive": {
      "type": "flow",
      "flowId": "0b7e6a52-3c1d-4f7a-9a55-2f4f6f1f9c10",
      "body": "Pode responder rapidinho por aqui?",
      "buttonText": "Responder"
    }
  }'
```

`body` é obrigatório. `buttonText` é opcional (padrão `Responder`, até 20 caracteres). Vale a mesma regra de qualquer mensagem de sessão: fora da janela a API recusa, e aí o caminho é o template. No dashboard, é o link **Formulário** ao lado de **Template** na caixa de Conversas.

## 3. Receber a resposta

Cada envio chega como [`message.flow_reply`](/webhooks/events#message-flow-reply). Leia de `data.fields`:

```json
{
  "event": "message.flow_reply",
  "data": {
    "id": "wamid.HBgM...",
    "from": "5588999990000",
    "to": "5588911110000",
    "flow_id": "0b7e6a52-3c1d-4f7a-9a55-2f4f6f1f9c10",
    "flow_name": "Captar contato",
    "source_message_id": "c0a8012e-7d2b-4a3f-8e11-9b1f4c2d7a66",
    "fields": {
      "nome": "Maria Souza",
      "email": "maria@exemplo.com",
      "interesse": "Falar com vendas",
      "obs": ""
    },
    "answers": [
      { "key": "nome", "label": "Seu nome", "value": "Maria Souza" }
    ]
  }
}
```

Os valores já vêm legíveis: opção escolhida chega com o texto da opção, múltipla escolha separada por vírgula, aceite como `Sim` ou `Não`, data como `dd/MM/yyyy`. Pergunta opcional sem resposta chega como string vazia, nunca ausente.

`source_message_id` é o id da mensagem da Arara que levou o botão. Use pra ligar a resposta ao envio ou à campanha.

A resposta também entra na conversa, no dashboard, como uma mensagem do cliente com o texto `Formulário respondido`.

## Consultar e desativar

```bash
curl "https://api.ararahq.com/v1/flows?page=0&size=20" -H "Authorization: Bearer ara_live_xxx"
curl "https://api.ararahq.com/v1/flows/{id}" -H "Authorization: Bearer ara_live_xxx"
curl "https://api.ararahq.com/v1/flows/{id}/responses?page=0&size=50" -H "Authorization: Bearer ara_live_xxx"
curl -X POST "https://api.ararahq.com/v1/flows/{id}/deprecate" -H "Authorization: Bearer ara_live_xxx"
curl -X DELETE "https://api.ararahq.com/v1/flows/{id}" -H "Authorization: Bearer ara_live_xxx"
```

Listas seguem o formato `{ data, pagination }`. Desativar impede que o botão abra pra quem já recebeu e mantém as respostas. `DELETE` só vale pra formulário que nunca foi publicado.

## Erros

| Status | `error.code` | Quando |
|---|---|---|
| 400 | `INVALID_FLOW` | Pergunta em branco, opções de menos, chave inválida ou JSON recusado pela Meta. |
| 403 | `PLAN_FEATURE_LOCKED` | Plano abaixo do Voo. |
| 404 | `FLOW_NOT_FOUND` | Formulário inexistente ou de outra organização. |
| 409 | `FLOW_NAME_TAKEN` | Já existe formulário com esse nome no número. |
| 409 | `FLOW_NUMBER_REQUIRED` | Nenhum número conectado. |
| 409 | `FLOW_NUMBER_GONE` | O número em que o formulário foi criado saiu da conta. |
| 409 | `FLOW_NOT_DRAFT` / `FLOW_NOT_PUBLISHED` | Ação que não cabe no estado atual. |
