Confirmação de pedido é o caso típico de template UTILITY: uma mensagem esperada pelo cliente, ligada a uma transação dele. Esta receita mostra os templates, o envio a partir do seu backend e o tratamento de falhas.

## Templates necessários

Quatro templates UTILITY, criados e aprovados por você. A Arara não cria templates de pedido automaticamente.

### 1. Pedido confirmado

```bash
curl -X POST https://api.ararahq.com/v1/templates \
  -H "Authorization: Bearer ara_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "pedido_confirmado",
    "category": "UTILITY",
    "language": "pt_BR",
    "body": "Pedido {{1}} confirmado.\n\nTotal: R$ {{2}}\nPagamento: {{3}}\nPrazo: {{4}}\n\nAvisamos quando for despachado.",
    "samples": { "1": "ARA-12345", "2": "147,90", "3": "Pix", "4": "2 dias úteis" },
    "buttons": [
      { "type": "URL", "text": "Ver pedido", "url": "https://meusite.com/pedido/{{1}}" }
    ]
  }'
```

### 2. Pedido enviado

```bash
curl -X POST https://api.ararahq.com/v1/templates \
  -H "Authorization: Bearer ara_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "pedido_enviado",
    "category": "UTILITY",
    "language": "pt_BR",
    "body": "Seu pedido {{1}} saiu para entrega.\n\nCódigo de rastreio: {{2}}\nTransportadora: {{3}}",
    "samples": { "1": "ARA-12345", "2": "BR123456789BR", "3": "Correios" },
    "buttons": [
      { "type": "URL", "text": "Rastrear", "url": "https://meusite.com/rastreio/{{2}}" }
    ]
  }'
```

### 3. Pedido entregue

```bash
curl -X POST https://api.ararahq.com/v1/templates \
  -H "Authorization: Bearer ara_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "pedido_entregue",
    "category": "UTILITY",
    "language": "pt_BR",
    "body": "Seu pedido {{1}} foi entregue.\n\nSe algo não estiver certo, responda esta mensagem.",
    "samples": { "1": "ARA-12345" }
  }'
```

### 4. Falha no pagamento

```bash
curl -X POST https://api.ararahq.com/v1/templates \
  -H "Authorization: Bearer ara_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "pagamento_falhou",
    "category": "UTILITY",
    "language": "pt_BR",
    "body": "Não conseguimos confirmar o pagamento do pedido {{1}}.\n\nMotivo: {{2}}\n\nVocê pode tentar de novo pelo link abaixo.",
    "samples": { "1": "ARA-12345", "2": "Cartão recusado" },
    "buttons": [
      { "type": "URL", "text": "Tentar novamente", "url": "https://meusite.com/checkout/{{1}}" }
    ]
  }'
```

**Sobre os templates:**

- `samples` é um objeto com o número da variável como chave.
- No botão de URL, `{{N}}` reaproveita a variável `N` do corpo. Só o trecho **depois da última `/`** do valor entra no link, então passe um identificador simples (id do pedido, código de rastreio), não uma URL inteira.
- A resposta traz o `id` (UUID). Acompanhe a aprovação com `GET /v1/templates/{id}/status` ou pelo webhook `template.updated`. O prazo de aprovação é da Meta.

## Enviar ao confirmar o pedido

Use uma chave de idempotência derivada do pedido e do evento. Se o seu job rodar de novo (retry, webhook reenviado pela loja), a Arara devolve a mensagem original em vez de enviar outra.

<CodeGroup>
```typescript Node.js
import { NodeSDK } from '@ararahq/sdk';

const sdk = new NodeSDK({ apiKey: process.env.ARARA_API_KEY! });

export async function notifyOrderConfirmed(order: Order) {
  return sdk.messages.send(
    {
      receiver: `whatsapp:${order.customer.phone}`,
      templateName: 'pedido_confirmado',
      templateVariables: [
        order.id,
        order.totalFormatted,
        order.paymentMethod,
        order.estimatedDelivery,
      ],
    },
    { idempotencyKey: `order-confirmed-${order.id}` },
  );
}
```

```python Python
import os
import httpx

# O SDK Python 1.8.1 não envia Idempotency-Key. Para envio idempotente, chame a API direto.
def notify_order_confirmed(order) -> dict:
    response = httpx.post(
        "https://api.ararahq.com/v1/messages",
        headers={
            "Authorization": f"Bearer {os.environ['ARARA_API_KEY']}",
            "Idempotency-Key": f"order-confirmed-{order.id}",
        },
        json={
            "receiver": f"whatsapp:{order.customer.phone}",
            "templateName": "pedido_confirmado",
            "templateVariables": [
                order.id,
                order.total_formatted,
                order.payment_method,
                order.estimated_delivery,
            ],
        },
        timeout=10.0,
    )
    response.raise_for_status()
    return response.json()
```

```php PHP
use GuzzleHttp\Client;

// O SDK PHP 1.8.1 não envia Idempotency-Key. Para envio idempotente, chame a API direto.
function notifyOrderConfirmed(object $order): array
{
    $http = new Client(['base_uri' => 'https://api.ararahq.com', 'timeout' => 10]);

    $response = $http->post('/v1/messages', [
        'headers' => [
            'Authorization' => 'Bearer ' . getenv('ARARA_API_KEY'),
            'Idempotency-Key' => "order-confirmed-{$order->id}",
        ],
        'json' => [
            'receiver' => 'whatsapp:' . $order->customer->phone,
            'templateName' => 'pedido_confirmado',
            'templateVariables' => [
                $order->id,
                $order->total_formatted,
                $order->payment_method,
                $order->estimated_delivery,
            ],
        ],
    ]);

    return json_decode((string) $response->getBody(), true);
}
```
</CodeGroup>

A API responde `202` com `{ id, status, mode, sender, receiver, body, cost, reason }`. `id` é o `ara_msg_...`; `status` vem em maiúsculas (`PENDING`, `SCHEDULED`, `PROCESSING`, `SENT`, `DELIVERED`, `READ`, `FAILED`, `CANCELED`).

**Idempotência:**

- Repetir a chave devolve a mensagem original, sem novo envio. A chave não expira e vale por usuário dono da chave de API.
- Em `POST /v1/messages` o conteúdo não é comparado: a mesma chave com outro destinatário ou outras variáveis também devolve a mensagem original. Se precisar reenviar de propósito (ex.: cliente corrigiu o telefone), use outra chave.
- Chave vazia, com mais de 255 caracteres ou com caracteres de controle é recusada.

Sem idempotência, o SDK PHP também serve: `$sdk->messages->send(receiver: ..., templateName: 'pedido_confirmado', variables: [...])`. Ver [SDK PHP](/sdks/php) e [SDK Python](/sdks/python).

## Enviar nas outras etapas

```typescript
export async function notifyOrderShipped(order: Order, trackingCode: string, carrier: string) {
  return sdk.messages.send(
    {
      receiver: `whatsapp:${order.customer.phone}`,
      templateName: 'pedido_enviado',
      templateVariables: [order.id, trackingCode, carrier],
    },
    { idempotencyKey: `order-shipped-${order.id}-${trackingCode}` },
  );
}

export async function notifyOrderDelivered(order: Order) {
  return sdk.messages.send(
    {
      receiver: `whatsapp:${order.customer.phone}`,
      templateName: 'pedido_entregue',
      templateVariables: [order.id],
    },
    { idempotencyKey: `order-delivered-${order.id}` },
  );
}

export async function notifyPaymentFailed(order: Order, reason: string, attempt: number) {
  return sdk.messages.send(
    {
      receiver: `whatsapp:${order.customer.phone}`,
      templateName: 'pagamento_falhou',
      templateVariables: [order.id, reason],
    },
    { idempotencyKey: `payment-failed-${order.id}-${attempt}` },
  );
}
```

De onde vêm os eventos:

| Etapa | Gatilho típico |
|---|---|
| Confirmado | Webhook de pedido pago da sua loja ou gateway |
| Enviado | Criação do envio (ex.: `fulfillments/create` no Shopify) |
| Entregue | Webhook do rastreador ou da transportadora |
| Pagamento falhou | Webhook do gateway de pagamento |

Para Shopify, ver [integração Shopify](/integracoes/shopify).

## Acompanhar a entrega

Não há método nos SDKs 1.8.1 para consultar a mensagem depois do envio. O status chega pelo webhook `message.status_updated`:

```json
{
  "event": "message.status_updated",
  "apiVersion": "...",
  "timestamp": "...",
  "organizationId": "...",
  "data": {
    "id": "ara_msg_...",
    "status": "failed",
    "receiver": "...",
    "sender": "...",
    "errorDetails": "..."
  }
}
```

No webhook o status vem em minúsculas: `queued`, `processing`, `scheduled`, `sent`, `delivered`, `read`, `failed`, `canceled`. Valide a assinatura antes de processar (ver [Webhooks](/webhooks)).

Com `failed`, leia `errorDetails` para decidir o que fazer. Se o número não recebe WhatsApp, caia para e-mail ou SMS no seu sistema. Ver [Erros de envio](/erros-de-envio).

## Depois da confirmação

Enviar o template **não** abre a janela de 24h. Ela abre quando o cliente responde. A partir daí:

1. **Brain responde** dúvidas como rastreio e troca, se configurado. Ver [Brain](/brain).
2. **Time responde** pelo dashboard em **Conversas**.
3. **Os dois**: Brain primeiro, humano quando precisa. Ver [Atendimento com vários atendentes](/recipes/inbox-support).

## Oferta pós-compra

Oferta de nova compra é MARKETING, não UTILITY: crie um template separado e envie só para quem aceitou receber marketing.

```bash
curl -X POST https://api.ararahq.com/v1/templates \
  -H "Authorization: Bearer ara_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "oferta_pos_compra",
    "category": "MARKETING",
    "language": "pt_BR",
    "body": "Oi {{1}}, obrigado pela compra de {{2}}. Na próxima, use o cupom CLIENTE10 para 10% de desconto.",
    "samples": { "1": "João", "2": "camiseta básica" }
  }'
```

## Checklist de produção

- [ ] 4 templates UTILITY aprovados
- [ ] Hooks da loja, transportadora e gateway disparando cada etapa
- [ ] `Idempotency-Key` por pedido e etapa em todo envio
- [ ] Telefone normalizado para E.164 (`+5511...`) antes de enviar; `(11) 99999-9999` precisa ser convertido
- [ ] Webhook `message.status_updated` com assinatura validada, tratando `failed`
- [ ] Alternativa (e-mail ou SMS) para quem não recebe no WhatsApp
- [ ] Oferta pós-compra só em template MARKETING e com consentimento
