Versão publicada: **1.8.1**. Python 3.8+. Dependências: `httpx`, `pydantic` v2, `pydantic-settings` e `tenacity`. O pacote instala como `ararahq-sdk` e importa como `arara_api_sdk`.

## Setup

```python
from arara_api_sdk import AraraClient

client = AraraClient(
    api_key="ara_live_xxx",              # ou variável ARARA_API_KEY
    base_url="https://api.ararahq.com",  # opcional, este é o default
    timeout=30.0,                        # opcional, em segundos
    max_retries=3,                       # opcional
)

# Fecha as conexões ao sair
with AraraClient() as client:  # lê ARARA_API_KEY do ambiente
    ...
```

Todas as opções também podem vir do ambiente: `ARARA_API_KEY`, `ARARA_BASE_URL`, `ARARA_TIMEOUT`, `ARARA_MAX_RETRIES`.

## Recursos disponíveis (1.8.1)

Todo método síncrono tem uma variante `_async` com a mesma assinatura.

| Recurso | Acesso | Métodos que funcionam |
|---|---|---|
| Messages | `client.messages` | `send(request)` |
| Templates | `client.templates` | `get(template_id)`, `get_status(template_id)`, `delete(template_id)` |
| Users | `client.users` | `me()`, `update(request)` |
| Organizations | `client.organizations` | `get_webhook()`, `update_webhook(request)`, `get_brain_config()`, `update_brain_config(request)`, `invite_user(request)`, `list_members()`, `list_numbers()`, `update_number(number_id, request)` |

`client.campaigns`, `client.brain` e `client.payments` existem no pacote, mas nenhum método deles funciona contra a API atual. Detalhes em **Limitações conhecidas**, no fim da página.

<Note>
  A branch `main` do repositório já tem `contacts`, `conversations`, `wallet`, `numbers`, `smart_links`, `api_keys`, retry em 429 e o campo `code` nas exceções, mas essa versão ainda não foi publicada no PyPI.
</Note>

## Enviar mensagem

```python
from arara_api_sdk import AraraClient
from arara_api_sdk.models.message import SendMessageRequest

with AraraClient(api_key="ara_live_xxx") as client:
    response = client.messages.send(SendMessageRequest(
        receiver="whatsapp:+5511999999999",
        template_name="confirmacao_pedido",
        template_variables=[
            "https://meusite.com/nota/123.pdf",  # header (mídia opcional)
            "João",                               # {{1}}
            "ARA-12345",                          # {{2}}
        ],
    ))

print(response.id)      # ara_msg_...
print(response.status)  # status inicial da mensagem
```

`SendMessageRequest` rejeita variáveis com quebra de linha ou tab (`ValidationError` do Pydantic, antes de chamar a API).

**Mensagem de sessão (texto livre, dentro da janela de 24h):**

```python
response = client.messages.send(SendMessageRequest(
    receiver="whatsapp:+5511999999999",
    body="Oi! Vi sua dúvida e respondo já já.",
))
```

O SDK não aceita chave de idempotência no envio e não tem método para consultar uma mensagem depois (o status chega pelo webhook `message.status_updated`).

## Async

```python
import asyncio
from arara_api_sdk import AraraClient
from arara_api_sdk.models.message import SendMessageRequest

async def main():
    async with AraraClient(api_key="ara_live_xxx") as client:
        return await asyncio.gather(*[
            client.messages.send_async(SendMessageRequest(
                receiver=phone,
                template_name="lembrete_aula",
                template_variables=["João"],
            ))
            for phone in ["whatsapp:+5511999990001", "whatsapp:+5511999990002"]
        ])

results = asyncio.run(main())
```

## Templates

`get`, `get_status` e `delete` recebem o **id** do template (UUID).

```python
from uuid import UUID

template_id = UUID("7f1c2e9a-3b4d-4c5e-8f60-1a2b3c4d5e6f")

status = client.templates.get_status(template_id)
print(status.status, status.rejection_reason)

template = client.templates.get(template_id)
print(template.name, template.provider_status)

client.templates.delete(template_id)
```

Para criar e listar templates, use a API direto por enquanto (ver limitações).

## Usuário e organização

from arara_api_sdk.models.organization import UpdateWebhookRequest

me = client.users.me()

client.organizations.update_webhook(UpdateWebhookRequest(url="https://meusite.com/webhooks/arara"))

## Erros

```python
import time
from arara_api_sdk import (
    AraraError,
    AraraAuthError,
    AraraValidationError,
    AraraRateLimitError,
    AraraResourceNotFoundError,
    AraraServerError,
    AraraConnectionError,
    AraraTimeoutError,
)

try:
    client.messages.send(SendMessageRequest(receiver="whatsapp:+5511999999999", body="oi"))
except AraraRateLimitError as e:
    time.sleep(e.retry_after or 1)
except AraraError as e:
    print(e.status_code, e.response_body)
```

| Exceção | Quando |
|---|---|
| `AraraValidationError` | 400 |
| `AraraAuthError` | 401 |
| `AraraResourceNotFoundError` | 404 |
| `AraraRateLimitError` | 429 (`retry_after` em segundos) |
| `AraraServerError` | 5xx |
| `AraraConnectionError` / `AraraTimeoutError` | falha de rede / timeout |
| `AraraError` | qualquer outro status, incluindo 403 |

Na 1.8.1, as exceções expõem `status_code`, `response_body` (o JSON da resposta) e a mensagem em `str(e)`. O código de erro da API fica em `e.response_body["error"]["code"]`. A API responde 403 (não 401) para chave inválida, então esse caso cai em `AraraError`. Lista de códigos em [Erros](/erros).

## Retry

Na 1.8.1, o SDK retenta 5xx, erro de conexão e timeout, com espera exponencial entre 2s e 10s, até `max_retries` vezes. **429 não é retentado**: trate `AraraRateLimitError`.

Hoje `max_retries=0` no construtor é ignorado (o default 3 continua valendo). Para desligar o retry, use a variável de ambiente `ARARA_MAX_RETRIES=0`.

<Warning>
  O retry reenvia `POST /v1/messages` em 5xx e o SDK não manda chave de idempotência. Se duplicar mensagem for inaceitável, desligue o retry.
</Warning>

## Limitações conhecidas

| Método | Problema |
|---|---|
| `messages.get` | Funciona, mas a API só devolve mensagens enviadas pela mesma chave/usuário; mensagem de outro membro da organização responde 403. |
| `templates.list` | A API responde `{ data, pagination }` e o SDK espera uma lista: falha ao validar. |
| `templates.create` | O modelo `CreateTemplateRequest` exige `structure_json` e não envia `body`, que a API exige: 400. |
| `campaigns.create` | Não envia o header `Idempotency-Key`, obrigatório na API: 400. |
| `brain.prompt` | Chama `POST /v1/brain`, rota que não existe na API. |
| `payments.create_pix` | Envia `amount`, a API lê `amountCentavos`: 400. |
| `payments.checkout` | Chama `POST /payments/checkout`, rota que não existe na API. |
| `scheduled_at` em `SendMessageRequest` | O `datetime` não é serializado para JSON; o envio quebra antes de chegar na API. |
