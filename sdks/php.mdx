## Instalar

```bash
composer require ararahq/sdk
```

[![Packagist](https://img.shields.io/packagist/v/ararahq/sdk)](https://packagist.org/packages/ararahq/sdk)

Versão estável publicada: **1.8.1**. Requer PHP 8.2+, `ext-json` e `guzzlehttp/guzzle` ^7.0. Autoload PSR-4 no namespace `Arara\`.

## Configurar

```php
use Arara\Arara;
use Arara\Config;

$sdk = new Arara(new Config(
    apiKey: getenv('ARARA_API_KEY'),
    baseUrl: 'https://api.ararahq.com', // opcional, este é o default
    timeout: 30,                        // opcional, em segundos
    retryTimes: 3,                      // opcional
    retryDelayMs: 100,                  // opcional, base do backoff
));
```

O SDK monta as URLs como `{baseUrl}/v1/...`. Não inclua `/v1` no `baseUrl`.

### Laravel

Registre o cliente como singleton e receba-o por injeção. Setup completo em [Integração Laravel](/integracoes/laravel).

```php
// app/Providers/AppServiceProvider.php
use Arara\Arara;
use Arara\Config;

public function register(): void
{
    $this->app->singleton(Arara::class, fn () => new Arara(new Config(
        apiKey: config('services.arara.key'),
    )));
}

// Em qualquer controller ou job
public function store(Request $request, Arara $sdk)
{
    $sdk->messages->send(
        receiver: 'whatsapp:' . $request->phone,
        templateName: 'confirmacao_pedido',
        variables: [$request->name, $request->orderId],
    );
}
```

## Enviar a primeira mensagem

Você precisa de plano assinado, número conectado, um template aprovado e saldo. Veja [Antes de começar](/quickstart#antes-de-começar). Troque `pedido_confirmado` pelo nome do seu template.

Salve como `enviar.php`:

```php
<?php

require 'vendor/autoload.php';

use Arara\Arara;
use Arara\Config;

$sdk = new Arara(new Config(apiKey: getenv('ARARA_API_KEY')));

$response = $sdk->messages->send(
    receiver: 'whatsapp:+5511999999999',
    templateName: 'pedido_confirmado',
    variables: ['João', '12345'],
);

echo $response['id'], PHP_EOL;     // ara_msg_...
echo $response['status'], PHP_EOL; // status inicial da mensagem
```

Rode:

```bash
ARARA_API_KEY=ara_live_... php enviar.php
```

Todos os métodos devolvem `array` (o JSON da resposta decodificado). O `receiver` precisa estar no formato `whatsapp:+<número>` (8 a 15 dígitos). Fora disso o SDK lança `ValidationException` sem chamar a API.

Com variáveis no corpo do template e mídia no header:

```php
$sdk->messages->send(
    receiver: 'whatsapp:+5511999999999',
    templateName: 'confirmacao_pedido',
    variables: [
        'https://meusite.com/nota/123.pdf', // header (mídia opcional)
        'João',                              // {{1}}
        'ARA-12345',                         // {{2}}
    ],
);
```

Para responder dentro da janela de 24h, mande `body` em vez de `templateName`:

```php
$sdk->messages->send(
    receiver: 'whatsapp:+5511999999999',
    body: 'Oi! Vi sua dúvida e respondo já já.',
);
```

Não há método para consultar uma mensagem depois do envio. O status chega pelo webhook `message.status_updated`.

## Templates

`get` e `delete` recebem o **id** do template (UUID), não o nome.

```php
// Listar: a resposta vem paginada
$page = $sdk->templates->list();
foreach ($page['data'] as $template) {
    echo $template['name'], ' ', $template['providerStatus'], PHP_EOL;
}

// Criar
$template = $sdk->templates->create([
    'name' => 'promo_natal',
    'category' => 'MARKETING',
    'language' => 'pt_BR',
    'body' => 'Oi {{1}}, oferta de Natal: {{2}}% off até {{3}}.',
    'samples' => ['1' => 'João', '2' => '30', '3' => 'sexta'],
]);

// Detalhe (inclui providerStatus e rejectionReason)
$detail = $sdk->templates->get($template['id']);

// Remover
$sdk->templates->delete($template['id']);
```

Não há método de status de template separado.

## Tratar erros

```php
use Arara\Exceptions\AraraException;
use Arara\Exceptions\RateLimitException;

try {
    $sdk->messages->send(receiver: 'whatsapp:+5511999999999', templateName: 'confirmacao_pedido');
} catch (RateLimitException $e) {
    sleep($e->retryAfter ?? 1);
} catch (AraraException $e) {
    echo "HTTP {$e->statusCode} {$e->errorCode}: {$e->getMessage()}";
    print_r($e->response);
}
```

| Exceção | Quando |
|---|---|
| `BadRequestException` | 400 |
| `AuthenticationException` | 401 |
| `NotFoundException` | 404 |
| `ValidationException` | 422, ou `receiver` inválido antes do envio |
| `RateLimitException` | 429 (`$retryAfter` em segundos) |
| `InternalServerException` | 500 |
| `AraraException` | qualquer outro status, incluindo 403 e 502/503 |

Todas ficam em `Arara\Exceptions\` e estendem `AraraException`, que expõe `$statusCode`, `$errorCode` (`error.code` da API), `$response` (corpo decodificado) e `getMessage()`. A API responde 401 para chave inválida, revogada ou expirada, e 403 quando o header `Authorization` está ausente ou a chave não tem permissão para a rota. Falha de conexão chega como exceção do Guzzle (`GuzzleHttp\Exception\ConnectException`), não como `AraraException`. Lista de códigos em [Erros](/erros).

## Retentativas e idempotência

Via middleware de retry do Guzzle, o SDK retenta até `retryTimes` vezes em erro de conexão, 429 e qualquer 5xx. Respeita `Retry-After` quando numérico; sem ele, espera `retryDelayMs × 2^(tentativa-1)`. Para desligar: `retryTimes: 0`.

<Warning>
  O retry reenvia `POST /v1/messages` em 5xx e `send` não aceita chave de idempotência. Se duplicar mensagem for inaceitável, use `retryTimes: 0` para envios.
</Warning>

## Webhooks

<Warning>
  Na 1.8.1, `WebhookUtils::verifySignature()` assina só o corpo, sem o timestamp, e nunca bate com `X-Arara-Signature`. Valide manualmente, como abaixo.
</Warning>

A string assinada é `"{X-Arara-Timestamp}.{corpo cru}"`. Valide antes de processar e trate o evento pelo campo `event`:

```php
$payload = file_get_contents('php://input');
$timestamp = $_SERVER['HTTP_X_ARARA_TIMESTAMP'] ?? '';
$signature = $_SERVER['HTTP_X_ARARA_SIGNATURE'] ?? '';
$secret = getenv('ARARA_WEBHOOK_SECRET');

$expected = 'sha256=' . hash_hmac('sha256', $timestamp . '.' . $payload, $secret);
$fresh = ctype_digit($timestamp) && abs(time() - (int) $timestamp) <= 300;

if (! $fresh || ! hash_equals($expected, $signature)) {
    http_response_code(401);
    exit;
}

$event = json_decode($payload, true);

switch ($event['event']) {
    case 'message.status_updated':
        $messageId = $event['data']['id'];   // ara_msg_...
        $status = $event['data']['status'];  // delivered, read, failed...
        break;
    case 'message.received':
        $from = $event['data']['from'];
        $body = $event['data']['body'];
        break;
}
```

Outros helpers de `WebhookUtils` também não reconhecem os eventos atuais (ver limitações). Detalhes do payload em [Webhooks](/webhooks). Controller Laravel pronto em [Integração Laravel](/integracoes/laravel#webhook).

## Recursos disponíveis

| Recurso | Acesso | Métodos |
|---|---|---|
| Messages | `$sdk->messages` | `send(receiver, templateName?, variables?, body?, mediaUrl?)` |
| Templates | `$sdk->templates` | `list()`, `get($id)`, `create($data)`, `delete($id)` |
| Users | `$sdk->users` | `getMe()`, `update($data)` (falham, ver limitações) |
| Organizations | `$sdk->organizations` | `getWebhook()`, `updateWebhook($data)` (falham, ver limitações) |

<Note>
  A branch `main` (`ararahq/sdk:dev-main`) já tem `contacts`, `conversations`, `wallet`, `numbers`, `smartLinks`, `campaigns`, `apiKeys` e a validação de assinatura de webhook corrigida, mas ainda não saiu em versão estável.
</Note>

## Limitações conhecidas

| Método | Problema |
|---|---|
| `users->getMe()` | Chama `/v1/users/me`; a rota da API é `/users/me`: 404. |
| `users->update()` | Mesmo path errado e usa POST (a API usa PATCH). |
| `organizations->getWebhook()` / `updateWebhook()` | Chamam `/v1/organizations/webhook`; a rota é `/organizations/me/webhook` (PATCH para atualizar). |
| `templates->get/delete` | Precisam do id (UUID). Com o nome a API responde 400. |
| `WebhookUtils::isInboundMessageEvent()` | Compara com `inbound_message`; a API envia `message.received`. |
| `WebhookUtils::isRevenueRecoveryEvent()` | Compara com `revenue_recovery`; a API envia `cart.abandoned`, `payment.failed`, `pix.created`, `boleto.due`. |
| `WebhookUtils::verifySignature()` (1.8.1) | Assina só o corpo, sem o timestamp: nunca bate com `X-Arara-Signature`. Corrigido na `main`. |
