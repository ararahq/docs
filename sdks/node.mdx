```bash
npm install @ararahq/sdk
```

[![npm](https://img.shields.io/npm/v/@ararahq/sdk)](https://www.npmjs.com/package/@ararahq/sdk)

Versão publicada: **1.8.1**. Pacote CommonJS com build ESM e tipos `.d.ts`. Depende de `axios`. O pacote não declara versão mínima de Node; o build de publicação roda em Node 20, então use Node 18 ou superior.

## Setup

```typescript
import { NodeSDK } from '@ararahq/sdk';

const sdk = new NodeSDK({
  apiKey: process.env.ARARA_API_KEY!,
  baseUrl: 'https://api.ararahq.com', // opcional, este é o default
  timeout: 10000,                     // opcional, em ms, default 10000
  maxRetries: 3,                      // opcional, default 3
});
```

A `apiKey` é obrigatória (o construtor lança `Error` sem ela) e usa o prefixo `ara_live_`. A Arara não tem modo de teste.

## Recursos disponíveis (1.8.1)

| Recurso | Acesso | Métodos |
|---|---|---|
| Messages | `sdk.messages` | `send(payload, options?)` |
| Templates | `sdk.templates` | `list()`, `create(payload)`, `get(id)`, `getStatus(id)`, `delete(id)` |
| Users | `sdk.users` | `getMe()`, `update(data)` |
| Organizations | `sdk.organizations` | `getWebhook()`, `updateWebhook(data)` |
| API Keys | `sdk.apiKeys` | `list()`, `create(mode?)` (ver limitações) |

Não há método para consultar uma mensagem depois do envio. O status chega pelo webhook `message.status_updated`.

<Note>
  A branch `main` do repositório já tem `contacts`, `conversations`, `wallet`, `numbers`, `smartLinks`, `campaigns` e um acesso REST genérico (`sdk.api`), mas essa versão ainda não foi publicada no npm. Até lá, chame esses endpoints direto pela API.
</Note>

## Enviar mensagem

```typescript
const response = await sdk.messages.send({
  receiver: 'whatsapp:+5511999999999',
  templateName: 'confirmacao_pedido',
  templateVariables: [
    'https://meusite.com/nota/123.pdf', // header (mídia opcional)
    'João',                              // {{1}}
    'ARA-12345',                         // {{2}}
  ],
});

console.log(response.id);     // ara_msg_...
console.log(response.status); // status inicial da mensagem
```

`variables` é aceito como apelido de `templateVariables`.

**Mensagem de sessão (texto livre, dentro da janela de 24h):**

```typescript
await sdk.messages.send({
  receiver: 'whatsapp:+5511999999999',
  body: 'Oi! Vi sua dúvida e respondo já já.',
});
```

## Idempotência

`send` aceita um segundo argumento com `idempotencyKey`, enviado no header `Idempotency-Key`:

```typescript
import { randomUUID } from 'node:crypto';

await sdk.messages.send(
  { receiver: 'whatsapp:+5511999999999', templateName: 'confirmacao_pedido', templateVariables: ['João'] },
  { idempotencyKey: randomUUID() }
);
```

Repetir a mesma chave devolve a mensagem original, sem novo envio. A API não compara o corpo: a mesma chave com destinatário ou variáveis diferentes também devolve a mensagem original, e a chave não expira. Use uma chave derivada do seu evento (ex.: id do pedido) para que retries da sua função não dupliquem a mensagem.

## Templates

Os métodos `get`, `getStatus` e `delete` recebem o **id** do template (UUID), não o nome. O parâmetro aparece como `name` na assinatura, mas a API só aceita o id.

```typescript
// Criar
const created = await sdk.templates.create({
  name: 'promo_natal',
  category: 'MARKETING',
  language: 'pt_BR',
  body: 'Oi {{1}}, oferta de Natal: {{2}}% off até {{3}}.',
  samples: { '1': 'João', '2': '30', '3': 'sexta' },
});

// Status de aprovação
const status = await sdk.templates.getStatus(created.id);
console.log(status.status, status.rejectionReason);

// Remover
await sdk.templates.delete(created.id);
```

`samples` é um objeto com o nome da variável como chave (`'1'` para `{{1}}`).

**Listar:** a API responde `{ data, pagination }`, mas o tipo de retorno declarado no SDK é `Template[]`. Até a correção, faça o cast:

```typescript
import type { Template } from '@ararahq/sdk';

const page = (await sdk.templates.list()) as unknown as {
  data: Template[];
  pagination: { page: number; size: number; totalElements: number; totalPages: number };
};
console.log(page.data.map((t) => t.name));
```

## Webhooks

O SDK exporta guards de tipo para o corpo do webhook:

```typescript
import { WebhookUtils } from '@ararahq/sdk';

function handleWebhook(payload: unknown) {
  if (WebhookUtils.isMessageStatusEvent(payload)) {
    console.log(payload.data.status, payload.data.receiver); // delivered, read, failed...
    return;
  }
  if (WebhookUtils.isInboundMessageEvent(payload)) {
    console.log(payload.data.from, payload.data.body);
    return;
  }
  if (WebhookUtils.isRevenueRecoveryEvent(payload)) {
    // cart.abandoned, payment.failed, pix.created, boleto.due
    console.log(payload.event, payload.data.phone);
  }
}
```

`WebhookUtils.parseEvent(payload)` devolve o evento se for um desses tipos, ou `null`. Os demais eventos (`conversation.needs_human`, `template.updated` etc.) não têm guard; trate pelo campo `event`.

O SDK **não** valida a assinatura. Valide antes de processar, com o corpo cru da requisição:

```typescript
import { createHmac, timingSafeEqual } from 'node:crypto';

const TOLERANCE_SECONDS = 300;

export function isValidAraraSignature(rawBody: string, timestamp: string, signature: string, secret: string): boolean {
  const ts = Number(timestamp);
  if (!Number.isInteger(ts) || Math.abs(Date.now() / 1000 - ts) > TOLERANCE_SECONDS) return false;
  const expected = 'sha256=' + createHmac('sha256', secret).update(`${timestamp}.${rawBody}`).digest('hex');
  const a = Buffer.from(expected);
  const b = Buffer.from(signature);
  return a.length === b.length && timingSafeEqual(a, b);
}
// timestamp = header X-Arara-Timestamp, signature = header X-Arara-Signature
```

## Erros

Toda falha lança `AraraError`:

```typescript
import { AraraError } from '@ararahq/sdk';

try {
  await sdk.messages.send({ receiver: 'whatsapp:+5511999999999', templateName: 'confirmacao_pedido' });
} catch (err) {
  if (err instanceof AraraError) {
    console.error(err.statusCode, err.code, err.message, err.details);
    if (err.statusCode === 429) {
      console.log('Tente de novo em', err.retryAfter, 'segundos');
    }
  }
}
```

| Campo | Conteúdo |
|---|---|
| `statusCode` | Status HTTP. Ausente em falha de rede. |
| `code` | `error.code` da API. `NETWORK_ERROR` sem resposta, `UNKNOWN_ERROR` quando a API não mandou código. |
| `message` | `error.message` da API. |
| `details` | `error.details` da API, quando houver. |
| `retryAfter` | Segundos do header `Retry-After`, quando houver. |

A API responde 403 (não 401) para chave inválida ou ausente. Lista de códigos em [Erros](/erros).

## Retry automático

O SDK retenta, até `maxRetries` vezes:

- falha de rede (sem resposta);
- 429, respeitando `Retry-After` (até 30s);
- qualquer 5xx.

O intervalo começa em 500ms e dobra a cada tentativa, até 30s. Outros 4xx não são retentados. Para desligar: `maxRetries: 0`.

<Warning>
  O retry vale também para `POST /v1/messages`. Se a API responder 5xx depois de aceitar o envio, a mensagem pode sair duas vezes. Passe `idempotencyKey` em todo envio.
</Warning>

## Limitações conhecidas

| Método | Problema |
|---|---|
| `apiKeys.*` | A API recusa gestão de chaves autenticada por API key (403). Crie e revogue chaves pelo dashboard. |
| `templates.list()` | Tipo de retorno errado (`Template[]` em vez de `{ data, pagination }`). Use o cast acima. |
| `templates.get/getStatus/delete` | Precisam do id (UUID). Com o nome do template a API responde 400. |
