A maioria dos erros da Arara sai num envelope com `code` estável. Algumas rotas ainda fogem dele; esta página diz quais e como tratar.

## Formato canônico

```json
{
  "error": {
    "code": "PLAN_FEATURE_LOCKED",
    "message": "Essa feature está liberada a partir do plano VOO_SOLO.",
    "details": {
      "feature": "CONTACTS",
      "currentPlan": "DECOLAGEM",
      "upgradeTo": "VOO_SOLO"
    }
  }
}
```

| Campo | Tipo | Descrição |
|---|---|---|
| `error.code` | string | Código estável. Use em `if`/`switch`. |
| `error.message` | string | Texto em português para exibir ou logar. Pode mudar. |
| `error.details` | object | Contexto do código (limites, plano, campo). Sempre presente, às vezes vazio. |

## Respostas fora do envelope

| Situação | Corpo |
|---|---|
| Falha de autenticação (`401`, e `403` sem header ou fora do escopo) | Padrão do Spring: `{ "timestamp", "status", "error", "path" }`, sem `code`. |
| Alguns `404` (`GET /v1/messages/{id}`, conversas, A/B, smart link) e o `403` de mensagem de outro usuário | Sem corpo. |
| Algumas validações de conversas, upload de mídia e histórico | `{ "error": "mensagem" }`, com `error` como string. |

Ramifique primeiro pelo status HTTP e só depois por `error.code` quando ele existir.

## Autenticação e permissão

| HTTP | Código | Quando |
|---|---|---|
| `401` | sem `code` | Chave inexistente, formato errado, revogada, expirada ou IP fora da allowlist. |
| `403` | sem `code` | Sem `Authorization`, rota que não aceita API key, ou chave sem permissão. |
| `403` | `RESOURCE_FORBIDDEN` | Recurso de outra organização, ou operação que só o painel faz (ex.: gerir chaves). |
| `403` | `FORBIDDEN` | Acesso negado por regra de segurança. |
| `401` | `API_KEY_REQUIRED` | Rota que só aceita API key foi chamada com sessão de usuário. |
| `403` | `VIEWER_READ_ONLY` | A chave pertence a um usuário com papel Leitor, que só acessa rotas de acompanhamento. |

## Plano, conta e carteira

| HTTP | Código | `details` | Quando |
|---|---|---|---|
| `403` | `PLAN_FEATURE_LOCKED` | `feature`, `currentPlan`, `upgradeTo` | Funcionalidade fora do plano. |
| `403` | `PLAN_LIMIT_REACHED` | `feature`, `current`, `max`, `currentPlan`, `upgradeTo` | Teto do plano (mensagens no mês, templates, automações). |
| `402` | `PLAN_REQUIRED` | `feature` | Exige assinatura paga. |
| `402` | `INSUFFICIENT_FUNDS` | `diagnostic` | Saldo insuficiente. |
| `403` | `ACCOUNT_NOT_ACTIVATED` | `currentStatus` | Conta ainda não ativada. |
| `403` | `ACCOUNT_BANNED` | — | Conta banida. |
| `403` | `ORGANIZATION_SUSPENDED` | — | Organização suspensa (decisão administrativa ou taxa de falha alta). |
| `403` | `NO_DEDICATED_NUMBER` | — | Operação exige número dedicado. |
| `403` | `IP_BLOCKED` | — | IP bloqueado. |
| `502` | `PAYMENT_PROVIDER_UNAVAILABLE` | — | Provedor de pagamento fora do ar. |

## Envio

Recusas antes do envio, em `POST /v1/messages`, `/v1/messages/batch` e campanhas:

| HTTP | Código | `details` | Quando |
|---|---|---|---|
| `422` | `RECIPIENT_OPTED_OUT` | `receiver` | Destinatário pediu para não receber. |
| `422` | `INVALID_RECIPIENT` | `receiver`, `reason` | Telefone fora do E.164. |
| `422` | `CONVERSATION_WINDOW_CLOSED` | `receiver` | Conteúdo livre com a janela de 24h fechada. |
| `422` | `TEMPLATE_PAUSED` | `templateName`, `providerStatus` | Template pausado. Pare o disparo. |
| `422` | `TEMPLATE_NOT_SENDABLE` | `templateName`, `providerStatus` | Template pendente, reprovado ou desativado. |
| `422` | `TEMPLATE_VARIABLES_MISMATCH` | `templateName`, `expected`, `received` | Quantidade de variáveis diferente do template. |
| `422` | `SENDER_NOT_ALLOWED` | `requestedSender`, `reason` | `sender` não pertence à organização ou não pode ser usado. |
| `403` | `NUMBER_BLOCKED` | — | Destinatário falhou repetidamente (inválido ou sem WhatsApp). Remova da base. |
| `403` | `FRAUD_SUSPECTED` | `reason` | Padrão de envio com cara de abuso. |
| `409` | `PROVIDER_NOT_RESOLVED` | `sender` | Número remetente não está pronto. Reconecte em Números. |
| `409` | `CONFLICT` | — | Template não encontrado na organização. |
| `429` | `SEND_RATE_LIMITED` | `scope`, `limit` | Teto de envio (inclui limite diário da chave). Traz `Retry-After`. |
| `429` | `MARKETING_FREQUENCY_EXCEEDED` | `receiver`, `limit`, `windowHours` | O contato já recebeu marketing demais na janela. Sem `Retry-After`. |
| `400` | `CAMPAIGN_SCHEDULE_TOO_SOON`, `CAMPAIGN_SCHEDULE_TOO_FAR` | `scheduledAt` | Agendamento de campanha fora de 5 minutos a 30 dias. |

### Códigos de diagnóstico (`ararahq-*`)

Algumas recusas de regra de negócio saem com um código de diagnóstico no lugar de `UNPROCESSABLE_ENTITY`, e `details.diagnostic` explica o que houve e o que fazer:

```json
{
  "error": {
    "code": "ararahq-invalid-number",
    "message": "Números de telefone inválidos no batch (use formato E.164): 5511",
    "details": {
      "diagnostic": {
        "code": "ararahq-invalid-number",
        "whatHappened": "Número inválido ou sem WhatsApp...",
        "howToAct": "Verifique se o número está correto no formato +55DDD9XXXXXXXX..."
      }
    }
  }
}
```

| Código | Significado |
|---|---|
| `ararahq-63016` | Janela de 24h fechada. |
| `ararahq-invalid-number` | Número inválido ou sem WhatsApp. |
| `ararahq-template-mismatch` | Variáveis não batem com o template. |
| `ararahq-invalid-recipient` | Template não encontrado ou destinatário inválido. |
| `ararahq-insufficient-funds` | Saldo insuficiente (dentro de `INSUFFICIENT_FUNDS`). |

## Recursos

| HTTP | Código | Quando |
|---|---|---|
| `404` | `TEMPLATE_NOT_FOUND` | Template não existe. |
| `404` | `CAMPAIGN_NOT_FOUND` | Campanha não existe. |
| `404` | `LINK_NOT_FOUND` | Link não existe. |
| `404` | `NOT_FOUND` | Rota inexistente. |
| `400` | `INVALID_PHONE` | Telefone inválido em opt-out ou LGPD. |
| `400` | `INVALID_AB_TEST`, `INVALID_WINNER` | Configuração de A/B inválida. |
| `400` | `INVALID_VERTICAL` | Vertical do perfil comercial fora da lista da Meta. |
| `422` | `GUPSHUP_APP_NOT_READY` | Operação de template sem número conectado. |

## Genéricos

| HTTP | Código | Quando |
|---|---|---|
| `400` | `VALIDATION_ERROR` | Campo obrigatório ausente ou regra de validação do corpo. `message` traz a primeira violação. |
| `400` | `INVALID_JSON` | JSON malformado, encoding errado, campo com tipo divergente ou obrigatório ausente. |
| `400` | `INVALID_PATH_PARAM` | ID na URL em formato errado (ex.: nome no lugar de UUID). `details.param`. |
| `400` | `INVALID_IDEMPOTENCY_KEY` | `Idempotency-Key` vazia, acima de 255 caracteres ou com caractere de controle. |
| `405` | `METHOD_NOT_ALLOWED` | Método HTTP errado na rota. |
| `409` | `CONFLICT` | Conflito de estado (nome duplicado, conteúdo bloqueado pela moderação). |
| `409` | `CONCURRENT_MODIFICATION` | Operação simultânea no mesmo recurso. Tente de novo. |
| `409` | `IDEMPOTENCY_CONFLICT` | Chave reutilizada com outros dados (só nas rotas de disparo por webhook). |
| `422` | `UNPROCESSABLE_ENTITY` | Regra de negócio sem código próprio. Leia `message`. |
| `429` | `RATE_LIMIT_EXCEEDED` | Rate limit geral. `Retry-After: 1`. |
| `500` | `INTERNAL_SERVER_ERROR` | Erro interno. |
| `500` | `MISSING_RATE_CARD` | Falha ao precificar. Tente de novo. |

<Note>
  Hoje, header ou parâmetro obrigatório ausente (`Idempotency-Key` em campanha, `count` na estimativa, `batchId`) cai no erro genérico e responde `500 INTERNAL_SERVER_ERROR`, não `400`.
</Note>

### Recuperação

| HTTP | Código | Quando |
|---|---|---|
| `404` | `RECOVERY_ENDPOINT_NOT_FOUND` | Endpoint ou ingestão não encontrado. |
| `403` | `RECOVERY_ENDPOINT_INACTIVE` | Endpoint de conversão desativado. O endpoint de recuperação não responde mais isso: desligado, ele devolve `REJECTED` com `NO_ACTIVE_AUTOMATION` quando nenhuma automação ativa escuta o evento. |
| `400` | `RECOVERY_EVENT_INVALID` | Tipo de evento ou período inválido. |
| `401` | `RECOVERY_HMAC_INVALID` | Assinatura HMAC não confere. |
| `429` | `RECOVERY_RATE_LIMITED` | Excesso de eventos. `Retry-After: 60`. |
| `404` | `RECOVERY_CONFIG_NOT_FOUND` | Sem configuração para o evento. |
| `412` | `RECOVERY_TEMPLATE_MISSING` | Template vinculado foi removido. |
| `402` | `RECOVERY_FREE_CAP_REACHED` | Cota gratuita de recuperação atingida. |

## Falha depois do aceite

`202 Accepted` não garante entrega. Quando a Meta recusa depois, a mensagem vira `FAILED` e:

- `GET /v1/messages/{id}` traz o motivo em `reason`;
- o webhook `message.status_updated` traz o motivo em `data.errorDetails`;
- o valor da mensagem é estornado na carteira.

O catálogo de motivos, com causa e solução, está em [Por que minha mensagem falhou](/erros-de-envio).

## Retry

- A Arara retenta sozinha falhas temporárias do provedor, com backoff exponencial que respeita o `Retry-After` do provedor. Você não precisa reenviar nesses casos.
- Erro de template, variável, destinatário ou conta **não** é retentado.
- Do seu lado: retente `429` (após `Retry-After`), `500`, `502` e `503`, sempre com `Idempotency-Key` para não duplicar envio.
- Não retente `4xx` que não sejam `429`: corrija a causa.

## Tratamento no cliente

```typescript
const res = await fetch('https://api.ararahq.com/v1/messages', { method: 'POST', headers, body });

if (res.ok) return res.json();

const payload = await res.json().catch(() => null);
const code = typeof payload?.error === 'object' ? payload.error.code : undefined;

switch (true) {
  case res.status === 401:
    throw new Error('API key inválida ou revogada');
  case res.status === 403 && !code:
    throw new Error('API key sem permissão para esta rota');
  case res.status === 429:
    await sleep(Number(res.headers.get('Retry-After') ?? 1) * 1000);
    return retry();
  case code === 'RECIPIENT_OPTED_OUT' || code === 'NUMBER_BLOCKED':
    return removeFromList();
  case code === 'TEMPLATE_PAUSED':
    return pauseCampaign();
  case code === 'INSUFFICIENT_FUNDS':
    return notifyFinance();
  case res.status >= 500:
    return retryWithSameIdempotencyKey();
  default:
    throw new Error(payload?.error?.message ?? `HTTP ${res.status}`);
}
```
