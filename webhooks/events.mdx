Todos os eventos usam o mesmo envelope. Esta página detalha o conteúdo de `data` em cada um.

<Note>
  Configuração, headers, assinatura e retry estão em [Webhooks](/webhooks).
</Note>

## Envelope

```json
{
  "event": "message.status_updated",
  "apiVersion": "2026-05-13",
  "data": {},
  "timestamp": "2026-09-15T14:32:15.234Z",
  "organizationId": "0e4f3c1e-5b6a-4c3d-9e8f-7a6b5c4d3e2f"
}
```

| Campo | Tipo | Descrição |
|---|---|---|
| `event` | string | Tipo do evento. |
| `apiVersion` | string | Versão do contrato. Hoje `2026-05-13`. |
| `data` | object | Conteúdo do evento. |
| `timestamp` | string (ISO 8601) | Quando a Arara gerou o evento. |
| `organizationId` | string (UUID) | Organização dona do evento. |

Cada requisição traz `X-Arara-Signature: sha256=<hex>`, calculado sobre `"{X-Arara-Timestamp}.{corpo}"`. Ver [Webhooks](/webhooks#validar-a-assinatura).

## Mensagens

### `message.status_updated`

Toda mudança de estado de uma mensagem enviada.

```json
{
  "event": "message.status_updated",
  "data": {
    "id": "ara_msg_k9Bf2Xq",
    "messageId": "0e4f3c1e-5b6a-4c3d-9e8f-7a6b5c4d3e2f",
    "internalId": "ara_msg_k9Bf2Xq",
    "providerSid": "wamid.HBgL...",
    "status": "delivered",
    "receiver": "whatsapp:+5511999999999",
    "sender": "whatsapp:+5511888888888",
    "errorDetails": null
  }
}
```

| Campo | Tipo | Descrição |
|---|---|---|
| `id` | string | ID da mensagem, o mesmo devolvido no envio. |
| `messageId` | string (UUID) | ID interno de banco. |
| `internalId` | string | Igual a `id`. |
| `providerSid` | string \| null | ID da mensagem no provedor (`wamid`). |
| `status` | string | `queued`, `scheduled`, `processing`, `sent`, `delivered`, `read`, `failed` ou `canceled`. |
| `receiver`, `sender` | string | Destinatário e remetente. |
| `errorDetails` | string \| object \| null | Motivo da falha. Ver abaixo. |

`queued` corresponde ao `PENDING` da API. `sent` cobre também o estado técnico `SENT_TO_PROVIDER`.

Quando `status` é `failed`, `errorDetails` traz o motivo **traduzido pela Arara**, e não o objeto cru da Meta:

- Números no provedor atual (Meta via Gupshup): **string** com o que aconteceu e o que fazer.

  ```json
  { "status": "failed", "errorDetails": "Passaram-se mais de 24h desde a última mensagem do cliente. A Meta exige um Template Aprovado para reabrir a conversa. Envie um Template Message para reabrir a janela de conversa com este cliente." }
  ```

- Números legados (Twilio): **objeto** com `code`, `whatHappened` e `howToAct`.

  ```json
  { "status": "failed", "errorDetails": { "code": "ararahq-invalid-number", "whatHappened": "Número inválido ou sem WhatsApp...", "howToAct": "Verifique se o número está correto..." } }
  ```

Trate os dois formatos com type guard. O catálogo de motivos está em [Por que minha mensagem falhou](/erros-de-envio).

### `message.received`

O cliente mandou mensagem para um número próprio da organização.

```json
{
  "event": "message.received",
  "data": {
    "id": "wamid.HBgL...",
    "from": "5511999999999",
    "to": "5511888888888",
    "body": "ok, recebi",
    "type": "text",
    "media_url": "",
    "media_type": "text",
    "media_content_type": "",
    "transcription_summary": "",
    "sender_name": "João Silva",
    "timestamp": "2026-09-15T14:36:00Z",
    "provider": "META"
  }
}
```

| Campo | Descrição |
|---|---|
| `id` | ID da mensagem no provedor. |
| `from` | Telefone do cliente, só dígitos (sem `+`). |
| `to` | Seu número, só dígitos. |
| `body` | Texto. Vazio quando é só mídia. |
| `type` | `text` ou `media`. |
| `media_url` | URL da mídia. Vazio quando não há. |
| `media_type` | `text`, `audio`, `image`, `video`, `document` ou `media`. |
| `media_content_type` | MIME da mídia. |
| `transcription_summary` | Resumo ou transcrição da mídia, quando disponível. |
| `sender_name` | Nome de perfil do cliente no WhatsApp. |
| `timestamp` | Quando a Arara processou a mensagem. |
| `provider` | `META` ou `TWILIO`. |
| `reply` | Só aparece quando o cliente tocou num botão ou numa opção de lista. Veja abaixo. |

Quando a mensagem é o toque num botão, `body` traz o texto que o cliente viu e `reply` diz qual opção foi:

```json
"reply": { "kind": "button", "id": "quero-pagar", "title": "Quero pagar" }
```

| Campo | Descrição |
|---|---|
| `kind` | `button` (botão de mensagem interativa), `list` (opção de lista) ou `template_button` (resposta rápida de template). |
| `id` | O `id` que você definiu ao enviar o botão ou a opção. Em `template_button` é o payload do botão do template. |
| `title` | O texto que o cliente viu. |

Decida pelo `id`, não pelo `title`: o texto pode mudar, o `id` é seu. Mensagem digitada não traz `reply`.

Não dispara para mensagem recebida no pool compartilhado, para palavras de opt-out ("SAIR", "PARAR", "STOP"...) nem para respostas de confirmação de agendamento.

### `message.echo`

Mensagem que **sua equipe** mandou pelo app do WhatsApp Business num número em coexistência. Permite manter o histórico completo no seu sistema.

```json
{
  "event": "message.echo",
  "data": {
    "id": "ara_msg_x1Y2z3W",
    "provider_id": "wamid.HBgL...",
    "conversation_id": "3f1c9a2b-...",
    "from": "5511888888888",
    "to": "5511999999999",
    "direction": "outbound",
    "source": "whatsapp_app",
    "body": "Oi João, já te ligo",
    "type": "text",
    "media_url": "",
    "media_type": "text",
    "media_content_type": "",
    "transcription_summary": "",
    "timestamp": "2026-09-15T14:37:00Z",
    "provider": "META"
  }
}
```

Mesmos campos de `message.received`, com o sentido invertido (`from` é o seu número) e mais `provider_id`, `conversation_id` (vazio quando não há conversa), `direction` e `source`. `timestamp` é o horário do aparelho.

### `message.flow_reply`

Resposta de um [formulário](/flows) enviado pelo cliente. As chaves de `fields` são as que você definiu ao criar o formulário e não mudam.

```json
{
  "event": "message.flow_reply",
  "data": {
    "id": "wamid.HBgM...",
    "from": "5588999990000",
    "to": "5588911110000",
    "flow_id": "0b7e6a52-3c1d-4f7a-9a55-2f4f6f1f9c10",
    "flow_name": "Captar contato",
    "source_message_id": "c0a8012e-7d2b-4a3f-8e11-9b1f4c2d7a66",
    "fields": { "nome": "Maria Souza", "email": "maria@exemplo.com" },
    "answers": [
      { "key": "nome", "label": "Seu nome", "value": "Maria Souza" },
      { "key": "email", "label": "Seu melhor e-mail", "value": "maria@exemplo.com" }
    ]
  }
}
```

`fields` é o atalho pra ler por chave; `answers` traz a pergunta junto, na ordem do formulário. `source_message_id` é a mensagem da Arara que levou o botão (vazio quando não dá pra determinar). Na conversa, a resposta aparece como mensagem do cliente com o texto `Formulário respondido`.

## Templates

### `template.updated`

Mudança de status de template: aprovação, reprovação, pausa ou desativação, inclusive pausa automática feita pela Arara.

```json
{
  "event": "template.updated",
  "data": {
    "templateId": "a7f3c1e2-4b5d-6789-abcd-ef0123456789",
    "name": "blackfriday_v3",
    "status": "REJECTED",
    "category": "MARKETING",
    "rejectionReason": "INVALID_FORMAT"
  }
}
```

`status` traz o valor do provedor (`APPROVED`, `REJECTED`, `PAUSED`, `PENDING`, `DISABLED`...). `rejectionReason` vem preenchido em reprovações.

### `template.category_changed`

A Meta reclassificou a categoria. Pode mudar o preço por mensagem.

```json
{
  "event": "template.category_changed",
  "data": { "name": "aviso_pedido", "old": "UTILITY", "new": "MARKETING" }
}
```

### `template.quality_updated`

```json
{
  "event": "template.quality_updated",
  "data": { "name": "blackfriday_v3", "quality": "LOW" }
}
```

## Campanhas

### `campaign.completed`

A campanha terminou de processar todos os contatos. Não significa que todas as mensagens foram entregues.

```json
{
  "event": "campaign.completed",
  "data": {
    "id": "7b3789fb-4c5d-6789-abcd-ef0123456789",
    "name": "Black Friday 2026",
    "status": "completed_with_errors",
    "totalMessages": 12500,
    "totalCost": 4793.75
  }
}
```

| Campo | Descrição |
|---|---|
| `status` | `completed`, `completed_with_errors` ou `failed`. Confira sempre: o nome do evento é o mesmo nos três casos. |
| `totalMessages` | Contatos da campanha. |
| `totalCost` | Valor debitado, em reais. |

Enquanto a campanha está em `AB_TESTING`, o evento não dispara. Cancelamento também não dispara este evento. Para métricas detalhadas, consulte `GET /v1/campaigns/{id}`.

## Cobranças

### `charge.sent`, `charge.paid`, `charge.failed`, `charge.canceled`, `charge.expired`

Uma [cobrança](/cobrancas) foi enviada ou mudou de status, venha de onde vier: conversa, template, automação ou [link da automação](/automacoes-webhook). Os cinco eventos têm o mesmo `data`.

```json
{
  "event": "charge.paid",
  "data": {
    "id": "3f1c9a20-5b7d-4e8a-9c11-2d4e6f8a0b12",
    "reference_id": "pedido-1042",
    "status": "PAID",
    "method": "PIX",
    "amount_cents": 5990,
    "description": "Plano mensal",
    "phone": "5588999990000",
    "contact_id": "a1b2c3d4-5e6f-4a7b-8c9d-0e1f2a3b4c5d",
    "automation_id": "0e4f3c1e-5b6a-4c3d-9e8f-7a6b5c4d3e2f",
    "run_id": "7c1d2e90-4b3a-4c8e-9f21-5a6b7c8d9e01",
    "source": "HOOK",
    "created_at": "2026-09-20T14:02:11Z",
    "paid_at": "2026-09-20T14:09:40Z"
  }
}
```

| Campo | Descrição |
|---|---|
| `id` | ID da cobrança na Arara. |
| `reference_id` | O seu número da cobrança. |
| `status` | `PENDING`, `PAID`, `FAILED`, `CANCELED` ou `EXPIRED`. |
| `method` | `PIX` ou `PAYMENT_LINK`. |
| `amount_cents` | Total, em centavos. |
| `description` | Descrição da cobrança. |
| `phone` | Telefone do cliente. |
| `contact_id` | Contato ligado à cobrança. |
| `automation_id`, `run_id` | Automação e execução que enviaram, quando houver. |
| `source` | `CONVERSATION`, `TEMPLATE`, `AUTOMATION` ou `HOOK`. |
| `created_at`, `paid_at` | Criação e pagamento. `paid_at` só vem preenchido em cobrança paga. |

O código Pix e o link de pagamento **nunca** vão no evento. `charge.expired` dispara quando o `expiresAt` passa sem pagamento.

## Conversas

### `conversation.needs_human`

O Brain passou a conversa para atendimento humano.

```json
{
  "event": "conversation.needs_human",
  "data": {
    "handoffId": "ara_hof_Hk3mP9q",
    "conversationId": "3f1c9a2b-...",
    "reason": "CUSTOMER_REQUEST",
    "summary": "Cliente pediu para falar com atendente sobre troca.",
    "createdAt": "2026-09-15T14:36:00Z"
  }
}
```

`reason` é texto livre. Valores comuns: `CUSTOMER_REQUEST`, `LOW_CONFIDENCE`, `MAX_MESSAGES`, `QUOTA_EXCEEDED`, `LEAD_QUALIFIED_HOT`, e motivos escritos pelo próprio Brain. `conversationId` pode vir `null`.

Para encerrar o atendimento: `POST /v1/brain/handoffs/{handoffId}/resolve` (chave `ADMIN`).

## Número e conta WhatsApp

### `number.status`

```json
{
  "event": "number.status",
  "data": { "status": "BANNED", "reason": "Violação de política", "phone": "5511888888888" }
}
```

| `status` | Campos extras | Quando |
|---|---|---|
| `BANNED` | `reason`, `phone` | A Meta baniu o número. Envio bloqueado. |
| `RESTRICTED` | `restriction`, `phone` | A Meta restringiu o número. |
| `ACTIVE` | `phone` | A Meta reabilitou o número. |
| `ONBOARDING_ERROR` | `reason` | A conexão do número não foi concluída. |

### `number.tier_updated`

Limite de envio ou sinalização de qualidade mudou.

```json
{
  "event": "number.tier_updated",
  "data": { "event": "upgrade", "tier": "TIER_10K" }
}
```

`event` é o evento da Meta em minúsculas (contém `flagged` quando a qualidade caiu, `unflagged` quando voltou). `tier` é `TIER_50`, `TIER_250`, `TIER_1K`, `TIER_2K`, `TIER_10K`, `TIER_100K`, `UNLIMITED` ou vazio.

### `number.name_status`

```json
{
  "event": "number.name_status",
  "data": { "decision": "approved", "reason": "" }
}
```

### `account.review`

```json
{
  "event": "account.review",
  "data": { "decision": "APPROVED" }
}
```

### `account.capability`

```json
{
  "event": "account.capability",
  "data": { "maxDailyConversationPerPhone": "1000", "maxPhoneNumbersPerBusiness": "2" }
}
```

Os valores vêm como string.

## NFS-e

### `nfse.invoice.authorized`, `nfse.invoice.rejected`, `nfse.invoice.cancelled`, `nfse.invoice.error`

Mudança de status de nota fiscal de serviço emitida pela Arara. `data` é o objeto da nota:

| Campo | Descrição |
|---|---|
| `id`, `emitterId` | Identificadores da nota e do emissor. |
| `status` | `AUTHORIZED`, `REJECTED`, `CANCELLED` ou `ERROR`. |
| `environment` | Ambiente da emissão. |
| `dpsSeries`, `dpsNumber`, `dpsId` | Identificação da DPS. |
| `competenceDate` | Competência. |
| `service` | Código, descrição, valor, retenção de ISS e município. |
| `taker` | Tomador, quando informado. |
| `chaveAcesso` | Chave de acesso, quando autorizada. |
| `errors` | Erros da SEFIN, quando rejeitada. |
| `authorizedAt`, `cancelledAt`, `cancelReason` | Datas e motivo. |
| `whatsappMessageId` | ID da mensagem de entrega da nota, quando enviada por WhatsApp. |
| `createdAt` | Criação. |

## Diagnóstico

### `webhook.test`

Disparado pelo botão de teste na tela de Webhooks do painel. Gera uma entrega real no histórico, sem efeito em mensagens, templates ou campanhas.

```json
{
  "event": "webhook.test",
  "data": {
    "test": true,
    "message": "Este é um teste disparado pelo dashboard. Se você está vendo isso, sua URL funciona.",
    "dispatchedAt": "2026-09-15T17:00:00Z"
  }
}
```
