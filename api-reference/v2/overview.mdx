**Base URL** `https://api.ararahq.com/api` (endpoints `/v1/...`) · **Auth** `Authorization: Bearer ara_live_xxx` (a chave define a org).

## As 3 chamadas do dia a dia

```bash
POST /api/v1/messages        { "receiver": "whatsapp:+5511987654321", "body": "Seu pedido saiu pra entrega" }
POST /api/v1/messages/batch  { "templateName": "promo_junho", "messages": [{ "receiver": "whatsapp:+5511987654321" }] }
GET  /api/v1/messages/{id}
```

`receiver` usa o formato `whatsapp:+55...` (prefixo do canal + E.164 com DDI). Ver [Enviar](/api-reference/v2/send) pra tudo que dá pra mandar (texto, mídia, botões, lista) e [Templates](/api-reference/v2/templates) pra criar template.

## Janela de 24h

A única regra do WhatsApp que importa: você só manda **texto/mídia livre** se o cliente te escreveu nas últimas 24h. Fora disso, só **template aprovado**.

A Arara aplica sozinha: dentro da janela, o envio de texto livre passa; fora, devolve um erro (`422 UNPROCESSABLE_ENTITY`) pra você mandar um template aprovado no lugar (nunca inventa nem manda cópia errada).

## Regras do contrato

| | |
|---|---|
| Erro (domínio) | `{ "error": { "code", "message", "details" } }` com `code` estável |
| Erro (auth/validação) | `{ "timestamp", "status", "error", "path" }` sem `code` — ramifique pelo status HTTP |
| Paginação | `{ "data": [...], "pagination": { "page", "size", "totalElements", "totalPages" } }` |
| Idempotência | header `Idempotency-Key` em qualquer POST que cria recurso |
