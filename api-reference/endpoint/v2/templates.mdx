Templates são as mensagens pré-aprovadas que podem ser enviadas fora da janela de 24h. Esta página cobre os endpoints. Categorias, regras de aprovação e política ficam em [Templates](/concepts/templates) e [Política de templates](/templates/policy).

**Base URL:** `https://api.ararahq.com`

Todas as rotas exigem conta ativa. Conta que ainda não foi ativada responde `403 ACCOUNT_NOT_ACTIVATED`.

## Criar template

`POST /v1/templates` · permissão `TEMPLATES_WRITE`

```bash
curl -X POST https://api.ararahq.com/v1/templates \
  -H "Authorization: Bearer ara_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "pedido_confirmado",
    "category": "UTILITY",
    "language": "pt_BR",
    "body": "Oi {{1}}, seu pedido {{2}} foi confirmado. Total: R$ {{3}}.",
    "footer": "Acompanhe pelo nosso site",
    "samples": { "1": "João", "2": "12345", "3": "147,90" }
  }'
```

Resposta (`201 Created`):

```json
{
  "id": "a7f3c1e2-4b5d-6789-abcd-ef0123456789",
  "name": "pedido_confirmado",
  "formattedName": "pedido_confirmado",
  "category": "UTILITY",
  "originalCategory": "UTILITY",
  "language": "pt_BR",
  "providerName": "GUPSHUP",
  "providerTemplateId": "…",
  "providerStatus": "PENDING",
  "rejectionReason": null,
  "availableForSending": true,
  "unavailableReason": null,
  "bodyPreview": "Oi {{1}}, seu pedido {{2}} foi confirmado. Total: R$ {{3}}.",
  "structureJson": {},
  "usageGuide": {
    "message": "Use o objeto 'variables' no envio da mensagem para substituir os placeholders.",
    "endpoint": "POST /v1/messages"
  },
  "variablesSchema": { "1": "João", "2": "12345", "3": "147,90" },
  "createdAt": "2026-09-15T14:30:00Z",
  "updatedAt": null
}
```

`providerStatus` fica em `PENDING` até a Meta decidir. O resultado chega pelo webhook [`template.updated`](/webhooks/events). O `id` é UUID.

### Parâmetros

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `name` | string | sim | Único na organização. |
| `category` | string | sim | `UTILITY`, `MARKETING` ou `AUTHENTICATION`. |
| `body` | string | sim | Texto com `{{1}}`, `{{2}}`... Não pode começar nem terminar com variável. |
| `language` | string | não | Default `pt_BR`. |
| `header` | string | não | Texto simples ou URL de mídia. |
| `headerType` | string | não | `text`, `media` ou `document`. |
| `footer` | string | não | Rodapé. |
| `samples` | objeto | não | Exemplo por número da variável: `{"1": "João"}`. A Meta usa na revisão. |
| `variableExamples` | string[] | não | Legado. Prefira `samples`. |
| `buttons` | array | não | Ver [botões](#botões). |
| `carouselCards` | array | não | Ver [carrossel](#carrossel). |

### Botões

```json
{
  "buttons": [
    { "type": "QUICK_REPLY", "text": "Confirmar" },
    { "type": "URL", "text": "Ver pedido", "url": "https://meusite.com/p/{{1}}" }
  ]
}
```

| `type` | Uso |
|---|---|
| `QUICK_REPLY` | Resposta rápida. |
| `URL` | Abre um link. Aceita variável no fim da URL. |
| `PHONE_NUMBER` | Liga para o número em `phone`. |
| `SMART_LINK` | Link rastreável da Arara. Ver [Smart Links](/smart-links). |
| `COPY_CODE` | Copia um código. |

Limites validados pela Arara: até 10 botões, texto de até 20 caracteres, no máximo 2 botões de link (`URL` + `SMART_LINK`) e 1 de telefone.

### Carrossel

```json
{
  "name": "produtos_destaque",
  "category": "MARKETING",
  "body": "Confira nossas ofertas da semana:",
  "carouselCards": [
    {
      "mediaUrl": "https://meusite.com/produto-1.jpg",
      "body": "Camiseta básica por R$ 79",
      "buttons": [{ "type": "URL", "text": "Comprar", "url": "https://meusite.com/p/1" }]
    },
    {
      "mediaUrl": "https://meusite.com/produto-2.jpg",
      "body": "Tênis de corrida por R$ 299",
      "buttons": [{ "type": "URL", "text": "Comprar", "url": "https://meusite.com/p/2" }]
    }
  ]
}
```

De 2 a 10 cards, cada um com mídia, texto e até 2 botões, todos com a mesma estrutura de botões.

### Autenticação (código de verificação)

Em `AUTHENTICATION` o conteúdo e o botão são fixos: a Arara envia à Meta o texto `{{1}} é o seu código de verificação` com um botão de copiar código, em `pt_BR`. `body`, `buttons` e `language` enviados não mudam o template aprovado. No envio, passe o código como única variável.

```json
{
  "name": "otp_login",
  "category": "AUTHENTICATION",
  "body": "Código de verificação"
}
```

## Criar a partir da biblioteca da Meta

Templates `UTILITY` que a Meta já aprovou. O template nasce aprovado, sem esperar revisão. Exige número conectado (`422 GUPSHUP_APP_NOT_READY` sem ele).

`GET /v1/templates/library?languageCode=pt_BR` · permissão `READ`

Devolve itens com `elementName`, `body`, `sampleText`, `header`, `topic`, `usecase`, `languageCode` e `buttons`.

`POST /v1/templates/library` · permissão `TEMPLATES_WRITE`

```bash
curl -X POST https://api.ararahq.com/v1/templates/library \
  -H "Authorization: Bearer ara_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{ "name": "confirmacao_pedido", "libraryTemplateName": "order_confirmation_1", "languageCode": "pt_BR" }'
```

`libraryTemplateName` é o `elementName` do item. Resposta `201` no mesmo formato de template.

## Listar templates

`GET /v1/templates` · permissão `READ`

```bash
curl "https://api.ararahq.com/v1/templates?status=APPROVED&page=0&size=50" \
  -H "Authorization: Bearer ara_live_xxx"
```

| Param | Tipo | Descrição |
|---|---|---|
| `name` | string | Nome exato. Devolve no máximo 1 item. |
| `status` | string | Filtra por `providerStatus` (`APPROVED`, `PENDING`, `REJECTED`, `PAUSED`...). |
| `page` | integer | Default `0`. |
| `size` | integer | Default `50`, máximo `200`. |

Header opcional `X-Waba-Id` restringe a uma WABA da organização.

Resposta (`200 OK`):

```json
{
  "data": [
    {
      "id": "a7f3c1e2-4b5d-6789-abcd-ef0123456789",
      "name": "pedido_confirmado",
      "category": "UTILITY",
      "providerStatus": "APPROVED",
      "availableForSending": true,
      "bodyPreview": "Oi {{1}}, seu pedido {{2}} foi confirmado. Total: R$ {{3}}."
    }
  ],
  "pagination": { "page": 0, "size": 50, "totalElements": 1, "totalPages": 1 }
}
```

<Note>
  `availableForSending: false` indica template aprovado num número que a organização não usa mais. A Meta aprova por número: recrie o template no número ativo.
</Note>

## Consultar template

`GET /v1/templates/{id}` · permissão `READ`

`id` é UUID. Passar o nome no lugar do ID responde `400 INVALID_PATH_PARAM`. Para buscar por nome, use `GET /v1/templates?name=`.

## Status de aprovação

`GET /v1/templates/{id}/status` · permissão `READ`

```json
{
  "status": "REJECTED",
  "rejectionReason": "INVALID_FORMAT",
  "category": "UTILITY"
}
```

Para templates no provedor atual, o status é o que a Arara recebeu do webhook do provedor, sem nova consulta. Para receber mudanças sem polling, escute [`template.updated`](/webhooks/events).

| Status | Significado |
|---|---|
| `PENDING` | Em revisão. |
| `APPROVED` | Pronto para enviar. |
| `REJECTED` | Reprovado. Veja `rejectionReason`. |
| `PAUSED` | Pausado pela Meta ou pela proteção automática da Arara. Envio responde `422 TEMPLATE_PAUSED`. |
| `DISABLED` | Desativado. Envio responde `422 TEMPLATE_NOT_SENDABLE`. |

## Sincronizar com a Meta

`POST /v1/templates/sync` · permissão `TEMPLATES_WRITE`

Importa templates criados direto no gerenciador da Meta e corrige status e categoria que divergiram.

```json
{
  "imported": ["promo_setembro"],
  "updated": ["pedido_confirmado"],
  "unchanged": 12,
  "skipped": []
}
```

## Métricas

`GET /v1/templates/{id}/analytics?period=30d` · permissão `READ`

```json
{
  "templateId": "a7f3c1e2-4b5d-6789-abcd-ef0123456789",
  "templateName": "pedido_confirmado",
  "period": "30d",
  "sent": 1250,
  "delivered": 1230,
  "read": 890,
  "failed": 10,
  "deliveryRate": "97.6",
  "readRate": "70.6"
}
```

`period`: `7d`, `30d` (default) ou `90d`. `sent` soma enviadas, entregues e lidas. As taxas vêm como **string** com 1 casa decimal, calculadas sobre `sent + failed`.

Para todos os templates de uma vez: `GET /v1/templates/analytics?period=30d` devolve um array com os mesmos campos (sem `templateId`), um item por nome de template.

## Apagar template

`DELETE /v1/templates/{id}` · permissão `TEMPLATES_WRITE`

Apaga primeiro na Meta e depois na Arara. Se a Meta recusar, nada é apagado. Resposta `204 No Content`.

<Warning>
  Irreversível. O histórico de envios continua, mas o template sai da listagem e não pode mais ser enviado.
</Warning>

## Limites do plano

Planos têm teto de templates **aprovados** (pendentes e reprovados não contam). No teto, a criação responde `403 PLAN_LIMIT_REACHED` com `details.current`, `details.max` e `details.upgradeTo`. Detalhe por plano em [Planos e limites](/business-rules/planos-e-limites).

## Erros

| HTTP | `error.code` | Quando |
|---|---|---|
| `400` | `VALIDATION_ERROR` | `name`, `category` ou `body` em branco. |
| `400` | `INVALID_JSON` | JSON malformado, ou `samples` enviado como array. |
| `400` | `INVALID_PATH_PARAM` | `id` não é UUID. |
| `403` | `ACCOUNT_NOT_ACTIVATED`, `PLAN_LIMIT_REACHED` | Conta não ativa ou teto do plano. |
| `403` | `RESOURCE_FORBIDDEN` | Template de outra organização. |
| `404` | `TEMPLATE_NOT_FOUND` | Template não existe. |
| `409` | `CONFLICT` | Nome já existe na organização, ou conteúdo bloqueado pela moderação da Arara. |
| `422` | `UNPROCESSABLE_ENTITY` | Categoria inválida, variável no começo ou fim do corpo, botões ou carrossel fora dos limites, exemplos faltando. |
| `422` | `GUPSHUP_APP_NOT_READY` | Biblioteca ou sincronização sem número conectado. |
