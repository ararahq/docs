A API da Arara é REST, JSON na entrada e na saída, com autenticação Bearer por API key. Esta página cobre as convenções gerais. Cada grupo de endpoints tem sua página, e a especificação completa fica na OpenAPI do projeto (`openapi.yaml`).

## Base URL

```
https://api.ararahq.com
```

Não há versão no host. Os paths de negócio começam em `/v1`. O prefixo `/api` (`https://api.ararahq.com/api/v1/...`) também é aceito por compatibilidade, mas use a forma sem prefixo.

## Autenticação

```
Authorization: Bearer ara_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

A chave é criada no painel. Chave sem permissões explícitas tem acesso total; chave restrita só alcança as rotas do seu escopo. Detalhes em [Autenticação](/api-reference/authentication).

## O que a API key alcança

| Grupo | Rotas principais | Página |
|---|---|---|
| Mensagens | `POST /v1/messages`, `POST /v1/messages/batch`, `GET /v1/messages/{id}` | [Mensagens](/api-reference/endpoint/v2/messages) |
| Conversas | `GET /v1/conversations`, `POST /v1/conversations/reply`, `POST /v1/conversations/window-status` | [Mensagens](/api-reference/endpoint/v2/messages#conversas) |
| Mídia | `POST /v1/media/upload` | [Mensagens](/api-reference/endpoint/v2/messages#upload-de-mídia) |
| Templates | `/v1/templates`, `/v1/templates/library`, `/v1/templates/sync` | [Templates](/api-reference/endpoint/v2/templates) |
| Campanhas | `/v1/campaigns`, `/v1/campaigns/estimate`, `/v1/campaigns/{id}/ab-test` | [Campanhas](/api-reference/endpoint/v2/campaigns) |
| Contatos, opt-out e LGPD | `/v1/contacts`, `/v1/opt-outs`, `/v1/contacts/{phone}/lgpd` | [Contatos](/api-reference/endpoint/v2/contacts) |
| Identidade da chave | `GET /auth/me`, `GET /auth/me/organizations` | [Identidade](/api-reference/endpoint/v2/auth) |
| Smart links, números, carteira, preços, perfil comercial, recuperação | `/v1/smart-links/whatsapp`, `/v1/organizations/me/numbers`, `/dashboard/wallet/balance`, `/v1/pricing/current`, `/v1/recovery/*` | `openapi.yaml` |

Gestão de chaves, configuração do webhook, pagamentos e perfil pessoal são operações do painel e **não** aceitam API key.

## Formato de resposta

Sempre JSON. Datas em ISO 8601 (UTC).

### Objeto único

```json
{
  "id": "ara_msg_k9Bf2Xq",
  "status": "PENDING",
  "mode": "LIVE",
  "sender": "whatsapp:+5511888888888",
  "receiver": "whatsapp:+5511999999999",
  "body": null,
  "cost": 0.3835,
  "reason": null
}
```

### Listas

O envelope padrão é `{ data, pagination }`:

```json
{
  "data": [{ "id": "a7f3c1e2-...", "name": "pedido_confirmado" }],
  "pagination": { "page": 0, "size": 50, "totalElements": 1, "totalPages": 1 }
}
```

<Warning>
  Nem toda lista segue o padrão ainda. Confira o envelope de cada rota:

  | Rota | Envelope |
  |---|---|
  | `GET /v1/templates`, `GET /v1/smart-links/whatsapp` | `{ data, pagination }` |
  | `GET /v1/campaigns` | `{ content, totalPages, totalElements }` |
  | `GET /v1/conversations`, `GET /v1/wallet/transactions` | `{ content, page, size, totalElements, totalPages }` |
  | `GET /v1/contacts` | `{ contacts, total, page, size, totalPages }` |
  | `GET /dashboard/messages` | `{ messages, total, page, size, totalPages }` |
  | `GET /v1/opt-outs` | `{ items, total }` (sem paginação) |
</Warning>

### Erro

```json
{
  "error": {
    "code": "INSUFFICIENT_FUNDS",
    "message": "Saldo insuficiente.",
    "details": {}
  }
}
```

Falha de autenticação e alguns `404` fogem desse formato. Lista completa em [Erros](/erros).

## Paginação

| Param | Tipo | Default | Descrição |
|---|---|---|---|
| `page` | integer | `0` | Página, começando em zero. |
| `size` | integer | varia | Itens por página. Default e máximo mudam por rota (ex.: templates 50/200, campanhas 20/100). |

```bash
curl "https://api.ararahq.com/v1/templates?page=1&size=50" \
  -H "Authorization: Bearer ara_live_xxx"
```

## Idempotência

| Endpoint | `Idempotency-Key` | Comportamento |
|---|---|---|
| `POST /v1/messages` | opcional | Mesma chave, mesmo usuário: devolve a mensagem já criada, sem reenviar nem cobrar. |
| `POST /v1/messages/batch` | opcional | Mesma chave: devolve o lote original. |
| `POST /v1/campaigns` | **obrigatório** | Mesma chave: devolve a campanha já criada. |

Regras que valem hoje:

- A chave tem de 1 a 255 caracteres, sem caracteres de controle. Fora disso: `400 INVALID_IDEMPOTENCY_KEY`.
- A chave não expira.
- O corpo **não** é comparado: reusar a chave com outro destinatário devolve a mensagem antiga, sem erro. Gere uma chave por intenção de envio.

```bash
curl -X POST https://api.ararahq.com/v1/messages \
  -H "Authorization: Bearer ara_live_xxx" \
  -H "Idempotency-Key: pedido-12345-confirmacao" \
  -H "Content-Type: application/json" \
  -d '{ "receiver": "+5511999999999", "templateName": "pedido_confirmado", "templateVariables": ["João", "12345"] }'
```

## Rate limits

| Tipo | Limite |
|---|---|
| Leitura (`GET`) autenticada | 1.200 por minuto |
| Escrita (`POST`, `PATCH`, `PUT`, `DELETE`) | 3.000 por minuto |

O limite é por usuário dono da chave. Toda resposta traz `X-RateLimit-Remaining`. Ao estourar:

```
HTTP/1.1 429 Too Many Requests
Retry-After: 1
X-RateLimit-Remaining: 0
```

```json
{
  "error": {
    "code": "RATE_LIMIT_EXCEEDED",
    "message": "Muitas requisições em pouco tempo. Aguarde e tente novamente.",
    "details": { "retryAfterSeconds": 1 }
  }
}
```

Além disso, o envio tem travas próprias: `SEND_RATE_LIMITED` (com `Retry-After`) e `MARKETING_FREQUENCY_EXCEEDED`. Ver [Erros](/erros#envio).

## Status HTTP

| Código | Quando |
|---|---|
| `200` | Sucesso com corpo |
| `201` | Recurso criado (template, opt-out) |
| `202` | Aceito para processamento (mensagem, lote) |
| `204` | Sucesso sem corpo (delete, cancelamento) |
| `400` | Payload ou parâmetro inválido |
| `401` | Chave inválida, revogada, expirada ou IP fora da allowlist |
| `402` | Saldo insuficiente |
| `403` | Sem `Authorization`, chave fora do escopo, plano ou conta sem permissão |
| `404` | Recurso não existe |
| `409` | Conflito de estado |
| `422` | Regra de negócio (opt-out, janela fechada, template não enviável) |
| `429` | Rate limit |
| `500` | Erro interno |
| `502` | Provedor externo indisponível |
| `503` | Serviço indisponível |

## Convenções

### Telefone

Envie em E.164. No envio de mensagem, `+5511999999999`, `5511999999999` e `whatsapp:+5511999999999` são aceitos. Em path (`/v1/contacts/{phone}`, `/v1/opt-outs/{phone}`) use sempre `+5511999999999`.

### IDs

| Recurso | Formato |
|---|---|
| Mensagem | `ara_msg_` + 7 caracteres base62 (campo `id` do envio) |
| Template, campanha, contato, conversa, smart link | UUID |

Rota que espera UUID e recebe outra coisa responde `400 INVALID_PATH_PARAM`.

### Valores monetários

Custos e saldos (`cost`, `totalCost`, `balance`, `threshold`, `amount`) vêm em **reais, decimal** (`0.3835`). Campos com sufixo `Cents` (`amountCents`, `monthlyPriceCents`) vêm em centavos inteiros.

### Enums

Em maiúsculas (`LIVE`, `MARKETING`, `APPROVED`), exceto no webhook `message.status_updated`, que usa minúsculas.

## CORS

A API só libera CORS para domínios da Arara. Chamada direta do navegador do seu cliente é bloqueada, e a chave nunca deve ir para o frontend: chame a API a partir do seu backend.
